# AGENTS.md — start here (any AI coding agent)

This file is for **every** AI agent working on this repo — Codex, Gemini, Cursor,
Copilot, Claude, anything. Several different agents (and accounts) take turns on
this project, so **this file + the docs it points to are the shared memory**.
Read it fully before touching anything, and **update the "In-flight work" table
below when you start, pause, or finish something.**

Read in this order:
1. **This file** — the owner, the rules, how work is organised, what's in flight.
2. **`CLAUDE.md`** — the project's dev notes. Despite the name, it applies to *all*
   agents: layout, build, deploy, tests, the 2D fragment map, the 3D overview.
3. **`3d/ARCHITECTURE.md`** — how the 3D game (the real game) is built: the core,
   `ctx`, the feature modules, the party (multiplayer) parity table, towns.
4. Then the feature you're touching: `3d/js/features/<id>/` and its test
   `scripts/tests3d/<id>.js`.

## 1. The project in one minute

**Lulu's Road Trip** — a browser game live at **https://lulu.boats** (GitHub
Pages from `main`), also shipped as an iOS app (Capacitor; Codemagic builds a
TestFlight build on every push to `main`).

- **2.0 = the 3D game in `3d/`** (three.js r170 vendored, plain ES modules, no
  build step, no framework). All new work goes here.
- **Classic 2D** (`classic.html` + `game.js`, generated from `src/`) is legacy:
  fix bugs only, never add features. `game.js` is generated — edit `src/`, run
  `node build.js`.
- Lulu (18) and her little sister Dina (8) — a frum Jewish family comedy:
  Lakewood, Midwood (Brooklyn), the highway, Bubbe's house, cholent, Shabbos,
  Chaverim/Shomrim/Hatzalah. These references are intentional and welcome.

## 2. The owner (adjust how you talk)

- **Not a coder.** Explain results in plain English: what changed for the
  player, what's live, what's left. No jargon, no code dumps.
- They test by playing on lulu.boats (phone, desktop, PS5 controller) and report
  bugs in casual messages. Reproduce before fixing.
- **Tone rules:** colourful low-poly cartoon, wholesome + silly. **Cartoon-only
  violence** (decided by the owner): robbers wave banana "guns", water pistols,
  confetti blasters; cops use stun nets and spike strips; nobody is ever shot, no
  blood, nobody hurt beyond the game's knock-down / lose-a-heart rules. Keeps the
  App Store **12+** rating. Dina's mode is strictly PG and never scary.

## 2b. Where the game is going (the owner's roadmap — agreed 2026-11-19)

game, more an open world; a weird mixture of Roblox and Fortnite; everything flows". Not a bigger map: a more
continuous one, where the car is something you use rather than the whole game. Every new piece is judged against that.

## 4. Setup and tests

> **How to run tests now (2026-11-27, `ci/fasttests`):**
> 1. `node scripts/affected.js` → the test files YOUR change can break, as a ready `groups=` string (`--why` explains).
> 2. Paste it: `gh workflow run smoke3d-full.yml --ref ci/<name> -f groups="<that string>"` — one dispatch per branch.
> 3. Every file runs on the **fast test clock** by default (~5–8× quicker, same checks); `-f clock=slow` = the old one.
> 4. Locally: `SMOKE3D_ONLY=<files> node scripts/smoke3d.js` (fast too); `SMOKE3D_PROF=1` shows where the time goes.
> 5. In a test, wait with `t.frames(n)` / `t.until(…)` — never a real-time sleep; a file that measures draws says `fast: false`.

```bash
node build.js --check                 # 2D game.js in sync with src/
node scripts/copy-web.js              # stage www/ for iOS + check every 3D file reference
node scripts/sw-version.js            # sw.json's key for every cache-first file (--check: fail if stale)
npm run serve                         # local server on :8099 → /3d/
npm run smoke                         # classic 2D smoke test (needs playwright)
SMOKE3D_ONLY=core,platform,law npm run smoke:3d   # 3D tests (needs playwright)
```

- Tests need Node 22 + `playwright` (`npm i -g playwright@1.56.1 && npx playwright install chromium`,
  or `NODE_PATH` pointing at an install). They boot the game in headless Chromium
  with a fake controller.
- 3D tests run in **software WebGL and are slow** (the full suite is ~2 h on one
  machine). Don't run everything locally — use CI:
- **CI (GitHub Actions):**
  - `smoke.yml` runs on every push (2D smoke + `core,platform,skip,ux,music`).
  - **"3D full suite"** (`smoke3d-full.yml`, manual) splits test files across up
    to 16 machines (~45 min). Inputs: `only` (comma list) or `groups`
    (`;`-separated groups, each on its own machine). Works on any branch:
    ```bash
    git push origin HEAD:ci/<name>
    gh workflow run smoke3d-full.yml --ref ci/<name> -f groups="core,platform,skip,ux;law;town"
    gh run list --workflow smoke3d-full.yml --branch ci/<name> --limit 1
    gh run view <run-id> --log-failed
    ```
    (Or GitHub → Actions → "3D full suite" → Run workflow.) Screenshots are
    uploaded as artifacts.
  - **The CI machines are shared by every agent and are the bottleneck** (2026-11-27: jobs waited 15–50 min for a
    machine). So: (1) ONE run per branch — a new dispatch on a branch CANCELS that branch's older run
    (`concurrency` in the workflow), so put everything you need in one dispatch; (2) ask only for the test files
    your change can affect + `core,platform` — not a long safety list; (3) `calm` alone takes ~60–85 min: run it once,
    on your final head, not on every iteration; (4) pack small files into shared groups (`groups="a,b,c;d,e"`), one
    machine per ~40 min of tests, instead of one machine per file; (5) a job is killed after 150 min.
  - **What to run: `node scripts/affected.js`** (vs `origin/main`; `--why` says why each file was picked) prints a
    ready `groups=` string for YOUR change, packed ~35 min per machine from `scripts/tests3d-durations.json`. Paste
    it instead of guessing a safety list. A core / HUD / world / model / harness change selects everything — then
    one full run on your final head. Refresh the durations after a full run: `node scripts/durations.js <run id>`.
  - **The fast test clock** (the DEFAULT; `SMOKE3D_FAST=0` / the workflow's `clock=slow` = the old clock):
    the picture is drawn every 6th frame on a small canvas, `t.frames` / `t.until` (and party3d's waits) hold the
    game exactly where they stop, the page's timers follow game time — same game time, same checks, ~5–8× fewer
    seconds. A file that measures draws / pictures says `fast: false` and keeps the old clock. Details:
    `scripts/smoke3d.js` › THE FAST TEST CLOCK, `3d/js/core/testclock.js`. `SMOKE3D_PROF=1` prints where a
    file's time goes (boot / draws / game step).
- Minimum before pushing a 3D change: `core,platform,skip,ux` + the test files of
  every feature you touched. Some tests are timing-sensitive on slow runners —
  if one fails, re-run it once before assuming you broke it, and check whether it
  also fails on `main`.

### One world: what the client needs from the wire (ci/friends → ci/oneserver, 2026-11-27)

`ci/friends` owns how other players are drawn and the rules (stage 3 "no ghosts", roadmap 28). `ci/oneserver` owns the wire. Stage 3 works on today's relay; these make it better.

**What stage 3 needs from the wire**
- Rooms by place, not random shards. Today EVERYONE is split at random over `lobby`…`lobby8` (≤ 24 each), so two people on the same street can be in different shards. Wanted: the room is the place (a stretch of the lap, a town, an interior's key), with a handoff as she moves. The client still draws only the nearest 6 on a phone and 8 on a desktop or TV, friends first.
- One snapshot per player, about 200 bytes at 5–7 a second: where she is (`s`/`d` on the lap, or the town's `x`/`z`), on foot or in a car, which room she's in, the car model + colour, the outfit code (`ctx.clothes.encode`, ≤ 40 characters), hair, what she holds (`ctx.houseitems.hand`, one item id), the emote, and her signed name ticket. Today's limits (2 KB a frame, 8 messages a second) fit this. The relay must pass unknown fields through, not strip them.
- Reliable one-time events: a bump, an emote starting, entering or leaving a room. Today these ride in snapshots for 1.5 s with a nonce, and the receiver drops duplicates (`party/net.js`). A server ack would replace that.
- A time ping, so every client knows the server's clock (see below).

**What I'd do with a shared world clock**
- Town loop traffic (minivans, buses) and the community cruisers are already computed from a seed + a clock in a party (`openworld` `townCarsAt(t)`, `community` `cruisersAt(t)`). I'd switch their clock from the party's to the world's, so every player sees the same loop cars, in a party or not.
- Highway traffic: a party run already seeds it (`T.configure(seed, t0)`). I'd seed the lap's traffic from the world clock for everyone. A car someone hits or jacks leaves its loop through the existing claim (`cl`), kept per room instead of per party. The extra random cars near you stay per screen, and other players' cars are followed like a car ahead (`traffic.leads`).
- The sky and weather: shared per party today (`ctx.party.atmosClock`). They would follow the world clock for all.
- Townsfolk, geese, households' days, seasons and the day's events already come from the calendar + a seed. They'd also match to the second.
- Until then: ambient traffic may differ between two screens (the owner accepted this). Each other, rooms you're both in, and what you do together must match.
